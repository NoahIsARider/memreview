# Design — CLS-inspired consolidation for memreview + a retention benchmark

> Status: **design only** (2026-08-21). No implementation yet.
> Two questions this document answers:
> 1. How does Complementary Learning Systems (CLS) theory map onto memreview,
>    and what would a "consolidation engine" look like?
> 2. How do we *know* memreview is better or more valuable than the
>    alternatives — a rigorous, honest evaluation design.

---

## Part 1 — CLS theory → memreview architecture

### 1.1 The theory in one paragraph

McClelland, McNaughton & O'Reilly (1995): the brain has two complementary
learning systems. The **hippocampus** learns fast, stores episodic snapshots
sparsely (pattern separation), and **replays** them — during rest/sleep,
interleaved with new experience — gradually training the **neocortex**,
which learns slowly, stores distributed semantic knowledge, and generalises.
The two stores answer different questions: *verbatim* ("what exactly did the
note say?") vs *gist* ("what do I actually know about this topic?"). Spaced
repetition works *because* it schedules exactly these replay/consolidation
events.

### 1.2 The mapping

| CLS concept | memreview today | memreview after |
|---|---|---|
| Hippocampus (fast, episodic) | raw `notes/*.md` + SRS items (verbatim, timestamped) | unchanged — **Store A** |
| Pattern separation | chunking (800-char overlapping windows) | unchanged |
| Neocortex (slow, semantic) | ❌ missing | **Store B**: `consolidated/*.md` — distilled topic summaries, versioned, with source refs |
| Replay / consolidation | SRS review events (agent grades an item) | SRS review **+** a background "sleep" pass that merges new facts into Store B |
| Interleaved learning | — | consolidation pass merges old + new material into one summary (anti-overwrite, anti-catastrophic-forgetting) |
| Retrieval = both stores | search hits verbatim chunks only | hybrid retrieval: verbatim hits (A) **+** gist hits (B), source-labelled |

### 1.3 The consolidation engine (new component)

**Data model — a consolidated knowledge unit:**

```json
{
  "id": "topic-0007",
  "title": "SQLite WAL vs DELETE",
  "content": "…distilled summary, LLM-generated…",
  "sources": ["notes/2026-08-01.md", "srs/ml-014"],
  "created": "2026-08-01",
  "last_replayed": "2026-08-21",
  "replay_count": 6,
  "version": 4
}
```

**Triggers** (both are "replay" events in CLS terms):
1. **Online**: after each SRS review batch, merge the reviewed items into
   their cluster's consolidated note.
2. **Offline ("sleep")**: nightly cron — incremental clustering pass.

**Algorithm (incremental, local, cheap):**
1. Embed new/updated notes + SRS items (existing `indexer.embed`).
2. Assign each to the nearest existing topic cluster by centroid cosine
   similarity; create a new cluster if above a distance threshold.
3. For each cluster with new material: LLM-distill
   `old_summary ⊕ new_facts → new_summary` (interleaving = the old summary is
   always in the prompt, so new material *extends* rather than replaces).
4. Update `version`, `last_replayed`, source refs. Store B is plain Markdown
   + one `consolidated/index.json` — same lock-in-free philosophy.

**Retrieval fusion**: `search()` returns Store A verbatim hits (as today) and
Store B gist hits, each labelled. A `gist` mode prefers Store B.

**Why this is defensible as CLS, not just a metaphor**: every mechanism has a
testable prediction — (a) consolidation should improve *gist* recall more than
verbatim; (b) interleaved merging should prevent "new note overwrites old
knowledge" (catastrophic forgetting); (c) SRS review + consolidation together
should flatten the forgetting curve more than either alone. Part 2 tests all
three.

## Part 2 — How do we know it's better? (evaluation design)

### 2.1 Position honestly first

memreview does **not** compete on the "store + retrieve" half (mem0, Basic
Memory, EverOS — embedding-model-bound, and we're on par at best). Its value
claim is the **review + consolidation half**, which no mainstream tool has.
So the benchmark must test *that* claim, and only use retrieval metrics to
show "no worse" (parity).

> Primary claim: *spaced-repetition review + consolidation measurably slow an
> agent's memory decay over time, at retrieval parity with store-only
> systems.*

If the data says review doesn't help — that's also a publishable, honest
finding. The benchmark is the artifact either way.

### 2.2 The retention benchmark ("AgentForget")

**Corpus (synthetic, deterministic):**
- 200 facts × 8 topics (25 each). Generated by a fixed-seed script, so anyone
  can reproduce the exact corpus.
- Three difficulty tiers:
  - *verbatim*: exact fact recall ("the deploy token expires on X")
  - *gist*: answer requires combining 2–3 facts
  - *confusable pair*: two facts with near-identical embeddings but different
    details ("server A: 2 GB RAM" / "server B: 4 GB RAM") — this is the CLS
    pattern-separation stress test; naive consolidation must fail here
- Query set: 3 queries per fact (verbatim / gist / distractors).

**Conditions (only the memory layer differs):**
- `C0 no-memory` — agent answers from its own context window only
- `C1 store-only` — retrieval works, no review, no consolidation
  (≈ mem0 / Basic Memory behaviour)
- `C2 memreview` — store + SRS review schedule (1/3/7/14/30)
- `C3 memreview-CLS` — store + review + consolidation (Part 1 engine)

**Protocol:**
1. Day 0: ingest all facts; run full query set (baseline).
2. Day 1/3/7/14/30: run query set again (no re-ingestion). Between
   checkpoints, C2/C3 surface *due* review items to the agent, which grades
   them (correct/wrong) and advances intervals; C0/C1 get nothing.
3. No ground-truth feedback on queries (a wrong answer must not become a
   learning event) — feedback is a separate future condition.

**Metrics:**
- Per checkpoint: recall@1 / recall@5, MRR
- Headline: **retention AUC** (area under the recall-vs-day curve) and
  **decay slope** (linear fit of recall over days) per condition
- Break out by tier: verbatim / gist / confusable
- System-level: consolidation faithfulness (LLM-as-judge: does the summary
  preserve facts?), cluster purity

**Confound controls:**
- Identical embedding backend + LLM across conditions (same Ollama model,
  same API model, same temperature)
- Same corpus, same query order (seeded)
- Review surface identical between C2 and C3 (only consolidation differs)
- ≥3 seeds per condition; report mean ± std

**Statistical plan:** paired comparison C2 vs C1 (is review better than
store-only?) and C3 vs C2 (does consolidation add value on top of review?)
with a Wilcoxon signed-rank or paired t-test on per-fact recall.

### 2.3 Retrieval parity check (fair fight, for completeness)

Optional Phase: same corpus, compare memreview search vs mem0 vs Basic Memory
on recall@k/MRR with their default embedding setups. Expected outcome:
parity. The point is to kill the objection "but retrieval is worse", not to
claim a win on someone else's turf.

### 2.4 Agent-task utility (optional Phase)

5–10 multi-session scenarios ("session 1: user sets constraints; session 5:
agent must apply them"). Metric: task success rate + turns-to-complete across
C0–C3. This is what reviewers of an agents paper will actually care about.

### 2.5 What makes this valuable for an application

- **Novelty**: no existing memory benchmark tests *retention over time* or
  *consolidation*; the "store+retrieve" benchmarks (mem0's, RAG suites) are
  static. This is a new benchmark with a new claim.
- **Rigor**: controlled conditions, seeded corpus, paired statistics — not a
  vibe comparison.
- **Artifact**: the harness itself is a clean open-source repo
  (`memreview-benchmark`), reproducible end-to-end.
- **Fallback**: even before any paper, the benchmark answers Noah's question
  in plain numbers — "our system vs store-only vs nothing, day 30 recall".

stop and publish the negative result honestly (still valuable). If it helps,
Phase B is justified.

## 5. Competitive landscape (research done 2026-08-21)

### Who's in the space

**Retrieval-focused (the crowded half):**
- mem0 (funded $24M): extraction + consolidation (similarity-merge + LLM
  conflict resolution) + relevance scoring; LoCoMo 92.5 / LongMemEval 94.4
- Zep/Graphiti: temporal knowledge graph; Basic Memory, O-mem, MemR3, MemOS

**Neuroscience-inspired (getting crowded fast):**
- HippoRAG (NeurIPS 2024): hippocampal indexing theory → schemaless KG +
  Personalized PageRank retrieval. Retrieval only — no review/consolidation
  scheduling.
- ZenBrain (arXiv 2604.23878, 2026): 7-layer TS architecture, 15 mechanisms
  — FSRS spaced repetition, Hebbian learning, SWS/REM sleep consolidation,
  synaptic homeostasis. Runs an *internal* 7-day sleep on/off simulation
  (350 facts), but: no cross-system comparison, no open benchmark artifact.
- TRUSTMEM (arXiv 2606.25161): learning trustworthy consolidation.
- Human-Inspired Memory Architecture (arXiv 2605.08538): multi-tier +
  offline consolidation + Ebbinghaus decay + reconsolidation. Design paper,
  no benchmark.
- RecMem: recurrence-based consolidation. Fang et al. 2025, SleepGate.

**Benchmarks:** LoCoMo, LongMemEval, BEAM, MemBench, MemTrace — **all static**
(retrieval/QA accuracy + token cost at one point in time). MemTrace adds a
"memory age" dimension (older facts degrade) but is still not a controlled
longitudinal intervention study. Industry commentary confirms the gap:
"static recall benchmarks don't predict multi-session agentic performance."

### The honest gap (our position)

We are **not** claiming to invent neuroscience-inspired memory — that space
is crowded. The defensible, publishable gap is:

1. **No open benchmark measures retention over time** (decay curves,
   day-0/1/3/7/14/30) with controlled conditions.
2. **No cross-system controlled experiment** (same corpus, same LLM, only
   the memory layer differs) answers "does review / consolidation actually
   flatten the forgetting curve, and by how much?"
3. **Active spaced-repetition review as an agent-facing intervention** is
   untested empirically (ZenBrain's sleep sim is internal, single-system).
4. Counter-position to ZenBrain's kitchen-sink: **5 mechanisms, each with a
   testable prediction, minimal implementation, measurement over breadth.**

> Thesis: *memory systems should be judged by how their users forget, not by
> static retrieval scores.* The benchmark is the contribution; memreview is
> the minimal local-first implementation that wins on it — or honestly
> reports the negative result.
